### Basic Git workflow

| Git operation | What it does |
|---|---|
| Check status | Shows the current changes in the repository |
| Stage changes | Selects files for the next commit |
| Commit changes | Saves the selected changes in Git history |
| View history | Shows previous commits |

### Branch and Pull Request

A branch is a separate line of work in a project. It allows developers to make changes without directly changing the main branch.

A Pull Request is used to request that changes from one branch be added to another branch. It also allows people to review the changes before merging.

### Git command glossary

| Command | Meaning |
|---|---|
| `git init` | Creates a new Git repository |
| `git status` | Shows the current repository status |
| `git add` | Stages changes |
| `git commit` | Saves staged changes |
| `git log` | Displays commit history |
| `git branch` | Lists branches |
| `git switch` | Switches between branches |
| `git push` | Sends commits to GitHub |
| `git pull` | Gets and integrates remote changes |

## 3. Commands

| Command / Tool | Purpose |

| VS Code | Edit the README files |

## 4. My understanding

I understood that Git is used to track changes in a project and GitHub is used to store repositories online and collaborate with others.

I learned that staging and committing are different steps. Staging selects the changes, while committing saves them in the project history.

I also understood that branches allow developers to work separately without directly changing the main branch. A Pull Request helps review changes before they are merged.
